# 서초 청년센터 QR 좌석관리 서비스 PRD v0.1

> **문서 상태:** 사용자와 함께 확정한 MVP PRD
>
> **최종 반영:** GitHub `main` 브랜치

## 1. 제품 정의

> **서초 청년센터 이용자는 좌석을 직접 관리하고, 운영자는 전체 좌석 상태를 확인할 수 있는 QR 기반 좌석관리 서비스**

MVP는 서리풀청년아트갤러리/센터의 1인석 9개를 대상으로 한다. 이용자는 좌석 현황을 확인하고, 현장 QR을 통해 이용을 시작하며, 이용시간을 선택·연장하고 퇴실한다. 좌석이 모두 이용 중인 경우에는 가장 먼저 이용 가능한 좌석을 예약할 수 있다. 운영자는 전체 좌석에 적용되는 이용 정책과 운영시간, 공지 문구를 관리한다.

## 2. 문제 정의

서초 청년센터 이용자는 어떤 좌석을 사용할 수 있는지, 현재 이용 중인 좌석은 언제 비는지 직관적으로 알기 어렵다. 또한 좌석 이용 시작·연장·퇴실을 스스로 관리할 수 있는 명확한 방법이 없다.

## 3. MVP 목표

MVP의 목표는 이용자가 직원의 별도 안내 없이 다음 행동을 완료할 수 있는지 확인하는 것이다.

1. 현재 이용 가능한 좌석과 예약 가능한 좌석을 확인한다.
2. 현장 QR을 통해 좌석 이용을 시작한다.
3. 원하는 이용시간을 선택하고 남은 시간을 확인한다.
4. 정해진 시간 안에 이용시간을 연장하거나 퇴실한다.
5. 빈 좌석이 없을 때 가장 먼저 이용 가능한 좌석을 예약한다.
6. 예약 좌석에 도착하면 QR을 스캔해 이용을 시작한다.

## 4. MVP 범위

### 포함 범위

| 영역 | 포함 기능 |
|---|---|
| 좌석 | 1인석 9개, 전체 좌석 동일 정책 |
| 이용자 계정 | 회원가입 없는 임시 계정 생성·로그인 |
| 좌석 현황 | 이용 가능·이용 중·예약 가능·정리 중 상태 표시 |
| 체크인 | 좌석 QR 스캔 후 이용시간 선택 및 이용 시작 |
| 이용시간 | 운영자가 설정한 단위와 최대 시간에 따른 선택지 제공 |
| 연장 | 이용 종료 30분 전부터 20분 전까지 운영자가 설정한 단위로 연장 |
| 예약 | 모든 좌석이 이용 중일 때 가장 짧게 남은 좌석에 선착순 1명 예약 |
| 예약 이용 | 예약 좌석의 QR 스캔으로 이용 시작 |
| 알림 | 예약·좌석 이동·연장 판단·예약 취소 관련 브라우저 알림 |
| 운영자 | 좌석 현황, 시간 정책, 운영시간, 공지 관리 |

### 제외 범위

- 이용자 및 운영자의 비밀번호 찾기·재설정
- 전화번호·이메일·카카오톡 연동
- 대기열 운영
- 운영자의 강제 퇴실·예약 취소·좌석 상태 강제 초기화
- 이용 통계 및 이용 이력 조회 화면
- 사전 예약 기능 및 이용 가능한 좌석의 예약
- 좌석별 개별 정책

## 5. 사용자와 권한

### 5.1 이용자

이용자는 임시 아이디와 비밀번호로 계정을 생성하고 로그인한다. 아이디는 이용자가 직접 입력한다. 이미 사용 중인 아이디를 입력하면 중복 안내를 표시하고 다른 아이디를 입력하도록 한다.

시스템은 사용자에게 표시되는 아이디와 별도로 무작위 내부 이용자 ID를 생성한다. 비밀번호는 평문으로 저장하지 않고 해시 처리한다. 이용자 계정에는 이메일·전화번호를 연결하지 않는다.

### 5.2 운영자

운영자는 이용자 계정과 분리된 운영자 전용 아이디·비밀번호로 로그인한다. 운영자 계정은 최초 배포 또는 초기 설정 시 생성한다. 운영자 인증 후에만 좌석 정책, 운영시간, 공지 관리 기능에 접근할 수 있다.

## 6. 이용자 계정 수명과 제한

| 항목 | 정책 |
|---|---|
| 계정 유형 | 임시 계정 |
| 만료 기준 | 마지막 행동 후 24시간 |
| 만료 처리 | 로그인 및 계정 기반 조작 권한 만료 |
| 비밀번호 분실 | 복구·재설정 없이 새 임시 계정 생성 |
| 활성 예약 | 계정당 1개 |
| 활성 좌석 이용 | 계정당 1개 |
| 운영 기록 | 내부 ID 기반의 익명 이벤트로 최소 보관 |
| 만료 시 대기 예약 | 자동 취소 |
| 만료 시 진행 중 이용 | 기존 이용시간과 좌석 상태 정책에 따라 처리 |

행동에는 로그인, 체크인, 예약, 연장, 퇴실, 예약 취소가 포함된다. 브라우저를 닫거나 화면을 보고 있는 것만으로는 행동이 갱신되지 않는다.

## 7. 좌석 상태

| 상태 | 이용자 화면 | 이용 가능 여부 |
|---|---|---|
| `AVAILABLE` | 이용 가능 | 현장 QR 체크인 가능 |
| `ACTIVE` | 이용 중, 종료 예정 시각, 남은 시간 | 신규 이용 불가 |
| `RESERVABLE` | 이용 중 정보와 예약 가능 배지 | 예약 가능 |
| `RESERVED` | 예약됨, 이용 시작 예정 시각 | 일반 체크인 불가 |
| `GRACE` | 정리 중, 이용 가능 예정 시각 | 체크인·예약 불가 |

`RESERVABLE`은 별도의 물리적 점유 상태가 아니라 `ACTIVE` 좌석 중 예약 조건을 충족한 좌석에 표시하는 예약 가능 표시다. 좌석 카드에는 색상만 사용하지 않고 상태 텍스트를 함께 표시한다.

## 8. 운영 정책

### 8.1 시간 단위와 최대 이용시간

운영자는 다음 시간 단위 중 하나를 선택한다.

- 10분
- 20분
- 30분
- 60분

운영자는 최대 이용시간을 설정한다. 최대 이용시간은 선택한 시간 단위의 배수여야 하며, 최대 240분까지 설정할 수 있다. 초기 기본값은 **30분 단위·최대 120분**이다.

시간 선택지는 단위부터 최대 시간까지의 배수로 자동 생성한다. 예를 들어 30분 단위와 최대 120분이면 `30분·60분·90분·120분`을 제공한다. 20분 단위와 최대 120분이면 `20분·40분·60분·80분·100분·120분`을 제공한다.

신규 체크인, 예약 이용, 연장은 모두 이용자가 시간을 선택한다. 기본 선택값은 최대 이용시간이다.

### 8.2 운영시간

운영자는 9개 좌석 전체에 공통으로 적용되는 운영시간을 설정한다.

- 요일별 이용 가능 시간 설정
- 특정 일자의 이용 가능 시간 설정
- 특정 일자 설정은 해당 날짜의 요일별 설정을 덮어씀
- 운영시간이 없는 요일 또는 날짜는 이용 불가

체크인, 예약 이용 시작, 연장은 운영시간 안에서만 허용한다. 이용 종료 시각은 운영 종료 시각을 넘을 수 없다. 운영 종료까지 선택한 시간 전체가 남지 않아도 이용을 시작할 수 있지만, 실제 이용은 운영 종료 시각에 끝난다.

운영 종료까지 최소 1개 시간 단위가 남아 있어야 신규 체크인을 허용한다. 예를 들어 30분 단위·18:00 운영 종료라면 17:30까지 체크인할 수 있고 17:31부터는 체크인할 수 없다.

운영자가 정책 또는 운영시간을 변경하면 신규 체크인·예약·연장부터 적용한다. 이미 진행 중인 이용 세션과 확정된 예약에는 소급하지 않는다.

예약 가능 구간, 예약자 도착 유예시간, 만료 후 정리 유예시간은 초기 정책값을 사용하되 운영자가 설정 화면에서 변경할 수 있다. 변경된 값은 신규 예약·신규 이용·신규 만료 처리부터 적용하며, 이미 확정된 예약과 진행 중인 세션에는 소급하지 않는다.

### 8.3 만료와 정리 유예

이용시간이 끝나면 좌석은 즉시 신규 이용 가능 상태가 되지 않고 정리 유예 상태로 전환한다. 정리 유예시간은 기본 10분으로 운영자 설정 대상이다. 유예가 끝나면 좌석은 `AVAILABLE`이 된다.

이용자는 선택한 이용시간이 끝나기 전에도 언제든 중도 퇴실할 수 있다. 이용자가 직접 퇴실하면 본인 세션을 즉시 종료하고 좌석을 `AVAILABLE`로 전환한다. 중도 퇴실로 남은 이용시간을 다른 이용자에게 이전하거나 환급하지 않는다. 해당 좌석에 예약이 있으면 최신 좌석 상태와 예약 정책에 따라 예약자에게 이용 가능 시각을 안내한다.

퇴실 요청은 로그인 상태와 본인 세션을 서버에서 확인한 뒤 처리한다. 계정이 만료되어 진행 중 세션만 남아 있는 경우에는 퇴실을 포함한 사용자 조작을 허용하지 않는다.

## 9. 예약 정책

### 9.1 예약 가능 조건

예약은 다음 조건을 모두 만족할 때만 가능하다.

1. 이용자에게 활성 예약이 없다.
2. 이용 가능한 좌석이 없다.
3. 모든 좌석이 이용 중이다.
4. 가장 짧게 남은 좌석이 종료까지 30분 이하 20분 초과 상태다.
5. 이용자가 로그인한 임시 계정으로 예약을 신청한다.

예약 가능한 좌석이 있더라도 이용 가능한 좌석이 하나라도 있으면 예약할 수 없다. 이용자는 빈 좌석의 QR을 스캔해 현장 이용을 시작해야 한다.

예약 대상 좌석은 이용자가 선택하지 않는다. 시스템은 예약 조건을 만족하는 좌석 중 남은 시간이 가장 짧은 좌석을 지정한다. 남은 시간이 같으면 좌석 번호가 빠른 좌석을 우선한다.

### 9.2 예약 시간과 선착순

예약자는 운영자가 설정한 시간 단위와 최대 이용시간에 따라 이용시간을 선택한다. 예약은 동일 좌석에 대해 선착순 1명만 확정한다. 대기열은 운영하지 않는다. 동시에 요청이 들어오면 서버가 먼저 확정한 한 건만 성공시키고 나머지는 예약 불가로 처리한다.

한 이용자는 동시에 하나의 활성 예약만 가질 수 있다. 예약자는 예약을 언제든 취소할 수 있다.

### 9.3 현재 이용자에 대한 연장 처리

예약이 생성되면 해당 좌석의 현재 이용자에게 브라우저 알림을 보낸다. 현재 이용자는 종료 30분 전부터 종료 20분 전까지 연장 여부와 연장 시간을 선택한다. 연장 시간은 운영자가 설정한 시간 단위의 배수로 선택한다.

현재 이용자가 연장하지 않으면 기존 종료 예정 시각 이후 예약자에게 좌석 우선권이 제공된다. 현재 이용자가 연장하면 예약자는 남은 시간이 가장 짧은 다른 좌석으로 즉시 이동한다. 좌석 이동 결과와 예상 이용 가능 시각은 예약자에게 브라우저 알림으로 안내한다.

좌석 이동이 발생하면 예약자가 선택한 이용시간은 그대로 유지한다. 예약자는 변경된 좌석과 새로운 이용 가능 시각을 안내받은 뒤 예약을 유지하거나 직접 취소할 수 있다. 예약자가 취소를 선택하면 예약만 해제하고 현재 좌석 이용자의 세션에는 영향을 주지 않는다.

예약자를 이동시킬 때는 기존 예약이 없는 다른 좌석 중 남은 시간이 가장 짧은 좌석을 우선 지정한다. 이동 가능한 좌석이 없으면 기존 예약을 유지하고, 현재 이용자가 연장한 좌석의 새로운 종료 예정 시각 이후로 예약 시작 시각만 변경한다. 이 변경 내용은 예약자에게 알림으로 안내하며, 예약자는 예약을 유지하거나 취소할 수 있다. 예약자 간 대기열은 만들지 않는다.

## 10. 예약 이용 시작

예약자는 기존 이용자의 종료 예정 시각부터 10분 이내에 예약 좌석의 QR을 현장에서 스캔해야 한다.

- QR 스캔 성공 시 예약은 이용 세션으로 전환된다.
- 이용시간은 예약 예정 시각이 아니라 실제 QR 스캔 시점부터 계산한다.
- 선택한 이용시간이 운영 종료 시각을 넘으면 운영 종료 시각에 종료한다. 따라서 다음 이용자는 센터 운영 종료 직전까지 이용할 수 있다.
- 10분 내 QR을 스캔하지 않으면 예약은 자동 취소된다.
- 자동 취소 후 좌석은 이용 가능 상태로 전환되며, 예약자에게 브라우저 알림을 보낸다.

## 11. 알림

브라우저 알림 권한을 허용한 이용자에게 다음 이벤트를 알린다.

| 대상 | 알림 이벤트 |
|---|---|
| 현재 이용자 | 자신의 좌석에 예약 생성, 연장 판단 필요 |
| 예약자 | 예약 확정, 좌석 이동, 예약 취소, 미도착 자동 취소 |

브라우저 알림 권한을 거부한 이용자도 핵심 기능을 사용할 수 있어야 한다. 이 경우 동일한 내용은 서비스 화면 내 상태와 안내로 제공한다. 전화번호·이메일·카카오톡 알림은 MVP에서 사용하지 않는다.

알림을 표시할 수 없는 경우에도 예약 상태, 좌석 이동, 연장 선택 마감 시각은 이용자 화면에서 확인할 수 있어야 한다. 브라우저 알림은 상태 확인을 대체하는 유일한 수단으로 사용하지 않는다.

## 12. 화면 구조

| 화면 | 주요 기능 |
|---|---|
| 이용자 로그인·임시 계정 생성 | 아이디·비밀번호 입력, 아이디 중복 안내 |
| 좌석 현황 | 9개 좌석 상태, 종료 예정 시각, 남은 시간, 예약 가능 배지, 공지 |
| QR 체크인 | 좌석 번호 확인, 이용시간 선택, 이용 시작, 공지 |
| 이용 중 세션 | 남은 시간, 종료 예정 시각, 연장, 퇴실, 예약 관련 안내 |
| 예약 | 자동 지정 좌석, 이용 가능 예정 시각, 이용시간 선택, 예약·취소 |
| 운영자 로그인 | 운영자 전용 인증 |
| 운영자 설정 | 시간 단위·최대 시간, 요일별·특정 일자 운영시간, 공지 1개 |
| 운영자 현황 | 전체 좌석 상태 확인 |

좌석 현황에서 예약 가능한 좌석은 좌석 카드에 `예약 가능` 배지를 표시하고 예약 버튼을 제공한다. 단, 실제 예약 좌석은 시스템이 자동 지정한다.

## 13. 공지

운영자는 전체 이용자 화면에 표시할 공지 1개를 작성·수정·삭제한다.

- 새 공지 저장 시 기존 공지를 덮어쓴다.
- 공지는 운영자가 직접 삭제할 때까지 표시한다.
- 시작일·종료일은 설정하지 않는다.
- 공지가 없으면 공지 영역을 표시하지 않는다.
- 좌석 현황, QR 체크인, 예약, 이용 중 세션 화면에 표시한다.
- 공지는 서비스 내에서만 표시하며 브라우저 알림으로 보내지 않는다.

## 14. MVP 성공 기준 초안

성공 기준의 목표값은 실제 현장 테스트 전에 함께 확정한다. 우선 다음 지표를 측정한다.

| 지표 | 정의 |
|---|---|
| 체크인 완료율 | 체크인 화면 진입 대비 체크인 완료 비율 |
| 예약 완료율 | 예약 가능 화면 진입 대비 예약 완료 비율 |
| QR 이용 성공률 | 올바른 좌석 화면으로 진입한 QR 스캔 비율 |
| 직접 퇴실 비율 | 자동 만료 전 이용자가 직접 퇴실한 세션 비율 |
| 예약 미도착률 | 10분 내 QR을 스캔하지 않아 자동 취소된 예약 비율 |
| 정책 문의 건수 | 이용자가 운영자에게 이용 규칙을 추가로 문의한 횟수 |

## 15. 계정 만료와 진행 중 세션

임시 계정이 마지막 행동 후 24시간이 지나 만료되어도 이미 시작한 좌석 세션은 기존 종료 시각까지 유지한다. 만료된 계정은 연장·퇴실·예약 취소를 포함한 사용자 조작을 할 수 없다. 해당 세션은 자동 만료 또는 운영 종료 정책에 따라 종료된다. 만료된 계정의 대기 중 예약은 자동 취소한다.

## 16. 정책 기본값

운영자가 별도로 변경하지 않은 초기 정책값은 다음과 같다.

| 정책 | 초기값 |
|---|---:|
| 시간 단위 | 30분 |
| 최대 이용시간 | 120분 |
| 예약 가능 구간 | 종료 30분 전부터 20분 전까지 |
| 예약자 도착 유예시간 | 10분 |
| 만료 후 정리 유예시간 | 10분 |

운영자는 위 정책값을 설정 화면에서 변경할 수 있다. 시간 단위와 최대 이용시간은 기존의 허용 규칙을 따르며, 시간 정책 변경은 신규 체크인·예약·연장부터 적용한다.

## 17. 구현상 상태 전이 원칙

예약 대상 좌석의 현재 이용자가 연장하면 기존 예약은 다른 좌석으로 이동한다. 시스템은 남은 시간이 가장 짧은 다른 좌석을 지정하고, 예약자의 선택 이용시간과 새로운 이용 가능 예정 시각을 유지·안내한다. 예약자는 이동 안내를 받은 뒤 예약을 유지하거나 취소할 수 있다.

예약자의 QR 스캔은 예약 좌석에 대한 이용 권한을 확정하는 원자적 상태 전이로 처리한다. 도착 유예시간이 끝난 뒤에는 QR 스캔을 통한 이용 시작을 허용하지 않는다. 좌석 상태 변경과 예약 상태 변경이 동시에 요청되는 경우 서버가 먼저 확정한 요청만 성공시킨다.
